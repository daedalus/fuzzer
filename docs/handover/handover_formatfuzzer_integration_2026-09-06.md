## 1. Goal

Add FormatFuzzer as first-class mutation operators inside fuzzer-tool by implementing thin `MutatorBase` wrappers.  

This is the **highest-ROI** integration path identified in the analysis:

- Reuses the existing `REGISTRY.register_mutator()` + `MutatorBase` contract (designed exactly for external engines).
- Gives the Elo / bandit / MCTS schedulers a new family of high-validity structural operators.
- Delivers the two modes evaluated in the paper (AFL+FFMut-style smart mutations and AFL+FFGen-style decision-seed generation) with almost no changes to the core loop.
- Avoids re-implementing checksum, length, ordering, and compression logic that FormatFuzzer already derives from binary templates.

**Non-goals for the first iteration**
- Full decision-seed corpus as the primary representation (phase 2).
- Shipping or vendoring the entire FormatFuzzer C++ toolchain inside this repo.
- Replacing the existing hand-written PNG/ZIP/ISO-BMFF/… mutators (they remain complementary).

---

## 2. Background (one-paragraph reminder)

FormatFuzzer compiles 010 Editor-style **binary templates** into C++ code that acts as:

1. **Generator** — produces valid (or near-valid) files from a *decision seed* (byte string of random choices).
2. **Parser** — turns an existing file into a decision seed that can regenerate it.
3. **Smart mutator** — abstract / replace / insert / delete logical chunks *on the decision seed*, then re-generates, automatically fixing sizes, checksums, chunk ordering, etc.

The paper shows high validity rates, thousands of files/s, and successful integration with AFL via both seed mutation and custom mutations. Bugs were found in ffmpeg and timidity.

fuzzer-tool already possesses stronger scheduling, rarity estimation, validity channel, FrameShift, and checksum learning than the original AFL experiments. Plugging FormatFuzzer in should amplify those results.

## 3. Architecture of the integration

```
┌─────────────────────────────────────────────────────────────┐
│                     fuzzer-tool main loop                    │
│  seed → pick operator (Elo/bandit/…) → mutate → execute →   │
│  coverage / rarity / validity feedback → reward operator    │
└───────────────────────────┬─────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│              REGISTRY (operator_registry.py)                 │
│  … existing 147 ops …                                       │
│  + ff_png, ff_zip, ff_isobmff, ff_generic, …                │
│    (MutatorBase instances registered at import / startup)   │
└───────────────────────────┬─────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│              FormatFuzzerMutator (MutatorBase)               │
│  mutate(data, rng, max_len, context) → bytes | None         │
│                                                             │
│  1. (optional) parse data → decision seed                   │
│  2. choose smart op: abstract | replace | insert | delete   │
│     | random-generate                                       │
│  3. call external FormatFuzzer binary / shared lib          │
│  4. return generated bytes (or None to decline)             │
│                                                             │
│  on_new_coverage(seed, new_edges) → optional reinforcement  │
└───────────────────────────┬─────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│         FormatFuzzer process / library (external)            │
│  - binary templates (PNG, ZIP, MP4, …) already compiled      │
│  - decision-seed ↔ file bidirectional transform              │
│  - smart chunk mutations that preserve context               │
└─────────────────────────────────────────────────────────────┘
```

Key design choices:

- **External process first** (simplest, no C++ build dependency inside fuzzer-tool). Later optional in-process via ctypes / cffi if throughput becomes limiting.
- **One mutator instance per major format** (or a single configurable `ff_generic` that takes a template name). Start with the formats that already have strong hand-written operators so A/B is easy: PNG, ZIP, ISO-BMFF/MP4, JPEG.
- **Decline is cheap and expected** (`return None`) when the input is not recognised or the smart mutation cannot be applied — same convention as every other operator.
- **Category = `"format"`** so the existing format-band scheduling and Elo arbitration treat them as peers of `png_chunk_mutate`, `zip_chunk_mutate`, etc.

## 4. Implementation plan (phased)

### Phase 0 — Prerequisites (½–1 day)

1. Build FormatFuzzer upstream (or obtain pre-built generators/parsers for PNG, ZIP, MP4, JPEG).
   - Confirm CLI / library interface for:
     - `parse(file) → decision_seed`
     - `generate(decision_seed) → file`
     - `smart_mutate(file_or_seed, op) → file`
   - If the public interface is only “generate from random seed”, implement the thin decision-seed round-trip ourselves by calling the generated C++ entry points.
2. Decide packaging:
   - **Option A (recommended for first PR):** external binaries on `$PATH` or under a configurable directory (`--ff-bin-dir`).
   - **Option B:** vendor the generated shared libraries for the 4–5 target formats.
3. Add a feature flag / config knob: `--formatfuzzer` / `--ff-templates png,zip,mp4` (default off).

### Phase 1 — Core mutator (1–2 days)  ← **high-ROI deliverable**

Create `src/fuzzer_tool/core/mutations/formatfuzzer.py`:

```python
"""FormatFuzzer-backed structure-aware mutators.

Wraps the external FormatFuzzer generators/parsers as MutatorBase
operators so the Elo/bandit schedulers can use them.
"""

from __future__ import annotations

import logging
import os
import subprocess
import tempfile
from pathlib import Path

from fuzzer_tool.core.mutator_interface import MutationContext, MutatorBase
from fuzzer_tool.core.operator_registry import REGISTRY

log = logging.getLogger(__name__)

# Default location; overridable via env or fuzzer config
_FF_BIN_DIR = Path(os.environ.get("FORMATFUZZER_BIN", "/usr/local/lib/formatfuzzer"))


class FormatFuzzerMutator(MutatorBase):
    """Smart structural mutations via FormatFuzzer decision seeds."""

    # Subclasses or instances set these
    name: str = "ff_generic"
    category: str = "format"
    template: str = "png"          # matches FormatFuzzer binary name
    max_attempts: int = 3

    def __init__(self, template: str = "png", name: str | None = None):
        self.template = template
        self.name = name or f"ff_{template}"
        self._bin = _FF_BIN_DIR / f"{template}_fuzzer"   # adjust to real names
        self._available = self._bin.exists() and os.access(self._bin, os.X_OK)
        if not self._available:
            log.debug("FormatFuzzer binary for %s not found at %s", template, self._bin)

    def is_available(self, ctx: MutationContext, data: bytes) -> bool:
        if not self._available:
            return False
        # Cheap magic-byte gate for the common formats; fall back to True
        # if we want the mutator to also attempt generation from non-matching seeds.
        return _looks_like(self.template, data) or len(data) < 16

    def mutate(
        self,
        data: bytes,
        rng,
        max_len: int = 0,
        *,
        context: MutationContext | None = None,
        **kwargs,
    ) -> bytes | None:
        if not self._available:
            return None

        op = rng.choice(["abstract", "replace", "insert", "delete", "random"])
        try:
            return self._run_ff(data, op, max_len or 4096, rng)
        except Exception:
            log.debug("FormatFuzzer %s failed for op=%s", self.template, op, exc_info=True)
            return None

    def _run_ff(self, data: bytes, op: str, max_len: int, rng) -> bytes | None:
        """Call the external FormatFuzzer binary.

        Concrete CLI is a placeholder — adjust once the real interface is confirmed.
        Expected contract:
          - stdin or -i file → input
          - -op abstract|replace|… 
          - -seed <int> for reproducibility
          - stdout → mutated bytes (or exit non-zero / empty on decline)
        """
        with tempfile.NamedTemporaryFile(suffix=f".{self.template}", delete=False) as tmp:
            tmp.write(data)
            tmp_path = tmp.name

        try:
            cmd = [
                str(self._bin),
                "--mutate",
                "--op", op,
                "--max-size", str(max_len),
                "--seed", str(rng.randint(0, 2**31 - 1)),
                tmp_path,
            ]
            result = subprocess.run(
                cmd,
                capture_output=True,
                timeout=2.0,          # hard ceiling; FormatFuzzer is normally << 10 ms
                check=False,
            )
            if result.returncode != 0 or not result.stdout:
                return None
            out = result.stdout
            if max_len and len(out) > max_len:
                out = out[:max_len]
            return out
        finally:
            try:
                os.unlink(tmp_path)
            except OSError:
                pass

    def on_new_coverage(self, seed: bytes, new_edges: int) -> None:
        # Optional later: keep a small success counter per (template, op)
        # so we can bias rng.choice in mutate().
        pass


def _looks_like(template: str, data: bytes) -> bool:
    if len(data) < 8:
        return False
    magics = {
        "png": b"\x89PNG\r\n\x1a\n",
        "jpeg": b"\xff\xd8\xff",
        "zip": b"PK\x03\x04",
        "mp4": None,          # ftyp box; more expensive check
        "isobmff": None,
    }
    magic = magics.get(template)
    if magic is None:
        return True
    return data.startswith(magic)


# ---------------------------------------------------------------------------
# Registration — import side-effect, same pattern as fractal_voronoi
# ---------------------------------------------------------------------------

def _register_default_templates() -> None:
    templates = os.environ.get("FORMATFUZZER_TEMPLATES", "png,zip,isobmff,jpeg").split(",")
    for t in templates:
        t = t.strip()
        if not t:
            continue
        try:
            REGISTRY.register_mutator(FormatFuzzerMutator(template=t))
        except ValueError:
            # already registered (e.g. under test re-import)
            pass

_register_default_templates()
```

Wire the module so it is imported at startup (same place `fractal_voronoi` and the Weizz mutators are pulled in). Typical locations:

- `src/fuzzer_tool/core/operator_registry.py` (bottom, next to the other self-registering imports), **or**
- `src/fuzzer_tool/core/mutations/__init__.py`, **or**
- an explicit import inside the Fuzzer constructor when `--formatfuzzer` is set.

Prefer the explicit flag path for the first PR so the operators stay dark until the binaries are present.

### Phase 2 — Decision-seed mode (optional, 1–2 days)

Once Phase 1 is stable:

- Maintain a side channel / parallel corpus of decision seeds.
- Add a thin operator `ff_seed_havoc` that mutates the decision seed with ordinary byte/bit operators and then calls the FormatFuzzer generator.
- This realises the paper’s AFL+FFGen strategy and lets the existing power schedules act on a higher-level representation.

### Phase 3 — Hardening & measurement (1 day)

- Respect `max_len` and the fuzzer’s adaptive length cap.
- Honour the validity channel (`--reject-code`) so FormatFuzzer’s high-validity outputs are credited on the *valid* coverage map.
- Add a simple success/failure counter per template (exposed in stats JSON).
- Timeout + resource limits on the subprocess (already sketched).
- Graceful degradation when the binary is missing (`is_available → False`).

## 5. Testing plan

1. **Unit / smoke**
   - `FormatFuzzerMutator.is_available` returns False when binary is absent.
   - `mutate` returns `None` on malformed input or subprocess failure (never raises into the main loop).
   - Round-trip: parse → generate produces a file that the corresponding hand-written parser (`parse_png_chunks`, etc.) still accepts.

2. **Operator registration**
   - After import (or flag enable) `REGISTRY.names()` contains `ff_png`, `ff_zip`, …
   - `REGISTRY.available(fuzzer, sample_png)` includes `ff_png`.
   - Category of the new operators is `"format"`.

3. **Paired A/B (the real acceptance test)**
   - Target: existing PNG / ZIP / MP4 harnesses under `targets/`.
   - Arms: baseline (no FormatFuzzer) vs `--formatfuzzer`.
   - Metrics (24 h, 10 seeds, same methodology as other handovers):
     - total edges / rare edges
     - valid-coverage edges (validity channel)
     - unique crashes / ASAN findings
     - execs/s (expect a modest drop; gate the operators if >15 % regression)
   - Use `tools/bench_paired.py` if it already exists; otherwise the same protocol used for the Weizz and Boltzmann A/Bs.

4. **Regression**
   - Existing format operators (`png_chunk_mutate`, …) still fire and receive reward.
   - No change to non-format campaigns when the flag is off.

## 7. Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Subprocess latency kills throughput | Hard 2 s timeout; later move to in-process library; let Elo learn to call the operators less often on easy targets |
| Binary missing / version skew | `is_available` → False; clear log message; feature stays dark |
| Over-generation of only valid inputs (misses error paths) | Keep all existing random/bit/byte/havoc operators; FormatFuzzer is an *additional* arm, not a replacement |
| Decision-seed interface differs from assumptions | Phase 0 explicitly verifies the CLI/library contract before coding the mutator |
| Duplicate effort with hand-written `png_chunk_mutate` etc. | Treat them as complementary; the schedulers will discover which combination works best per target |

The single richest source. FFmpeg's own tools/target_dec_fate.list in the upstream repo contains 656 crash reproductions, each downloadable via:
https://oss-fuzz.com/download?testcase_id=<ID>
Mapping format: <issue_num>/<testcase_id>  target_dec_<codec>_fuzzer
The <testcase_id> is a 16-digit number extracted from the file name. Example download:
wget -O crash.mpeg4 "https://oss-fuzz.com/download?testcase_id=4707817137111040"
84 unique codec fuzz targets span every FFmpeg decoder: h264, hevc, mpeg4, vp9, vp8, av1, aac, flac, tiff, png, jpeg2000, dirac, dnxhd, exr, snow, cfhd, magicyuv, rasc, wmv2, rv40, dca, eac3, opus, webp, g2m, prosumer, truemotion2, dxtory, ulti, ffvhuff, scpr, paf_video, xan_wc3, a_ac3_fixed, etc.
These are the seeds you need — each is a minimized crash input that already triggers ASAN/MSAN/TSAN/UBSAN. The raw bytes reveal which op mutators (byte-level, bit-flip, dictionary, structural) are relevant per format.

3. Google Security Research Advisories — Inline PoC Scripts
https://github.com/google/security-research/security/advisories/GHSA-vhxg-9wfx-7fcj
- CVE-2022-2566 — Heap OOB write in build_open_gop_key_points() in libavformat/mov.c
- Vector: Crafted MP4/MOV file
- PoC: Inline poc.py script in the advisory that generates the malicious MP4
- Root cause: Integer overflow in sc->sample_offsets_count = sum of ctts_data[i].count → av_calloc allocates too small → subsequent writes to sc->sample_offsets[k++] go OOB
- Same pattern: sc->open_key_samples_count overflow → sc->open_key_samples[k++] write OOB
- Format insight: The MP4 stsd, ctts, and sgpd atoms are the mutation targets. Op mutators that fuzz these atom sizes, sample counts, and sync group indices are directly motivated.
https://github.com/google/security-research/security/advisories/GHSA-39q3-f8jq-v6mg
- CVE-2025-9951 — Heap-buffer-overflow write in JPEG2000 decoder (libavcodec/jpeg2000dec.c)
- PoC: Base64-encoded poc.jp2 (inline in advisory)
- Root cause: Channel Definition (cdef) atom mismatches component-to-channel mapping. A cdef with cn=0, asoc=2 on a YUV420P frame writes full-resolution Y data into the smaller U chroma plane, overflowing by 64*16 = 1024 bytes
- Format insight: JPEG2000 codestream has SOC, SIZ, COD, QCD, PPT, SOT, SOD markers. The cdef marker segment is the key mutation target. Marker-segment-length fields and component-mapping entries are the op mutator seeds.
4. DepthFirstDisclosures / ffmpeg-dfvuln127 — AV1 RTP Depacketizer RCE
GitHub: https://github.com/DepthFirstDisclosures/ffmpeg-dfvuln127
- Bug: Heap buffer overflow in libavformat/rtpdec_av1.c — av1_handle_packet()
- Vector: Single 183-byte crafted RTP/AV1 packet delivered via RTSP
- Primitive: OOB write to AVBuffer.free function pointer → PC hijack to 0xdeadbeef
- PoC files: exploit.py (RTSP server), Dockerfile (builds vulnerable commit d12791ef7f), run_demo.sh
- Format insight: AV1 OBU (Open Bitstream Unit) structure — temporal delimiter, tile list OBUs. The obu_size field is the mutation target. The TD-skip path that advances pktpos without allocating is the bug. Op mutators targeting OBU header byte 0 (for OBU type) and the obu_size varint encoding are key seeds.
5. Y5neKO / CVE-2026-8461-EXP — MagicYUV Heap OOB Write (PixelSmash)
GitHub: https://github.com/Y5neKO/CVE-2026-8461-EXP
- Bug: Heap OOB write in libavcodec/magicyuv.c — magy_decode_slice()
- Vector: Crafted AVI file with MagicYUV codec
- Primitive: 640-byte OOB write to AVBuffer.free → system() hijack
- PoC files: exploit_cve_2026_8461.py (AVI generator), auto_calibrate.py (debug builds), auto_calibrate_nosym.py (production), full analysis docs
- Format insight: MagicYUV AVI structure with BMH5/BMH6 chunks. The slice_height field in the stream header (avih → strh → MagicYUV header) is the key mutation target. When slice_height doesn't evenly divide coded_height, the last slice's sheight (uncramped) vs height (clamped) mismatch causes dst to point past the buffer. Op mutators targeting slice_height values that create uneven remainders (e.g., 31 for 640-wide frames) are the seeds.
6. fm0ss / CVE-2025-9951-ffmpeg-jp2-poc — JPEG2000 RCE Research
GitHub: https://github.com/fm0ss/cve-2025-9951-ffmpeg-jp2-poc
- Bug: JPEG2000 component-mapping mismatch → callback pointer overwrite in libavcodec/jpeg2000dec.c
- PoC files: poc.jp2 (450-byte), generate_poc.py (self-contained payload generator), geometry.py (finds safe 112x18 geometry), run_poc.gdb (GDB launch script), WRITEUP.md
- Format insight: JPEG2000 SIZ marker (image dimensions), COD marker (coding style), QCD marker (quantization). The component-mapping (CCOM) and channel-definition (CDEF) markers are the mutation targets. The 112x18 geometry is a seed that triggers the overflow safely.
7. Fi1ix / exploitarium-06-29 — FFmpeg RASC DLTA Calc PoC
GitHub: https://github.com/Fi1ix/exploitarium-06-29/tree/main/ffmpeg-rasc-dlta-calc-poc
- Bug: Heap-buffer-overflow in libavcodec/rasc.c — decode_dlta() run types 4, 7, 12, 13
- Vector: Crafted RASC bitstream in AVI container (RIFF FourCC RASC)
- Primitive: 32-bit write past end of 64-byte PAL8 plane row → callback pointer hijack → calc execution
- PoC files: Self-contained C harness using libavcodec API, exploit_get_buffer2() custom callback, ASAN evidence at rasc.c:421
- Fix: Guard cx + 4 <= w * s->bpp before every 32-bit read/write in DLTA run handlers
- Format insight: RASC INIT/DLTA chunk structure. The DLTA run-type byte and x/y/w/h coordinate fields are the mutation seeds. A 64-pixel width with PAL8 (1 bpp) creates a 64-byte row where a 32-bit write at offset 63 crosses the boundary.

How to Extract Op Mutators and Seeds
For each format, the seed is the field/structure that the vulnerability's fix patch touches:
Format	Seed Field	Vulnerability	Fix Pattern
MagicYUV (AVI)	slice_height in stream header	CVE-2026-8461: last slice sheight > height → OOB write	Add dst + height * stride > buf_end check before write loop
JPEG2000 (.jp2)	cdef atom cn/asoc mapping	CVE-2025-9951: full-res Y → subsampled U plane	Validate component resolution matches channel mapping
MOV/MP4	ctts atom count fields	CVE-2022-2566: integer overflow in sample_offsets_count	Add overflow check before av_calloc
AV1 over RTP	obu_size in OBU header	DFVULN-127: TD skip advances cursor without allocating	Advance buf_ptr alongside pktpos
RASC (AVI)	DLTA run type + x/w/h coords	CVE: 32-bit write crosses 64-byte row boundary	Check cx + 4 <= w * bpp before 32-bit access
TIFF (.tif)	Strip size vs. decompressed bytes	CVE-2026-70631: memcpy copies all rows regardless of zlib output	Check zlib decompressed size before memcpy
DVBSub (WTV)	Parse buffer size in dvbsub_parser.c	CVE-2026-70628: signed integer overflow wraps guard	Check for negative/wrapped parse_offset
CFHD	Tag order/multiplicity in CFHD chunks	Multiple CVEs: SEGV, OOM, null deref, left shift	Validate tag order/mulitplicity per spec
shorten (.shn)	Packet size in ffconcat	CVE-2026-65704: size decrement wraps to near-SIZE_MAX	Bounds-check size before memcpy
Each downloaded crash testcase (from oss-fuzz.com/download) gives you the raw byte structure of a crashing input — examine the format's header magic, length fields, and codec-specific markers to derive the exact byte positions where op mutators should apply structured mutations (byte flips on size fields, bit flips on flags, dictionary mutations on FourCC codes, etc.).
Quick-start download script
# 1. Fetch all 656 OSS-Fuzz FFmpeg crash reproductions
curl -sSL https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/tools/target_dec_fate.list | \
  while read line; do
    [ -z "$line" ] && continue
    echo "$line" | grep -q '^#' && continue
    testcase_id=$(echo "$line" | sed -E 's/.*-([0-9]+)$/\1/')
    fuzzer=$(echo "$line" | sed 's/.*  //')
    wget -q "https://oss-fuzz.com/download?testcase_id=${testcase_id}" \
         -O "crashes/${fuzzer}/${testcase_id}"
  done
# 2. Fetch FATE seed samples
rsync -vauL --chmod=Dg+s,Duo+x,ug+rw,o+r,o-w,+X \
    fate-suite.ffmpeg.org:/home/samples/fate-suite/ ~/fate-suite/
